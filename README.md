# Ye Liu — personal research site

A static site: plain HTML, CSS and JavaScript. There is no build step, it makes no external requests (fonts are self-hosted), and it also works when you open `index.html` straight from disk.

## Files

| File | What it is |
|---|---|
| `index.html` | The page: hero, About, Highlights, research themes, the publication lists and the (empty) figure viewer. Text is plain HTML, except the Highlights cards and the publication lists, which `main.js` builds (the cards also have a static copy, see "Static copy of the cards"). |
| `assets/publications.js` | The data: `window.PUBLICATIONS` (papers) and `window.PATENTS`. The publication lists, the Highlights cards, the counts and the filters are built from it. **Generated file, do not edit by hand:** see "Publications and highlights" below. |
| `assets/main.js` | Builds the page from the data and runs the filters, deep links, figure viewer, section highlighting and light/dark toggle. The only parts you may need to edit are near the top: `TOPICS` (topic tab labels) and `SHORT` (short paper names, used on the Highlights cards). |
| `assets/style.css` | Styles. Colours are the custom properties at the top: light theme in `:root`, dark theme in `:root[data-theme="dark"]`. There is one accent colour (`--accent`). `--band` is the faint background of the Highlights section, and `--side` is the width of the left column of each publication (venue badge and figure). |
| `assets/figures/` | One figure per paper, `<id>.webp`, and a small copy of each in `thumb/`, see "Figures" below. |
| `assets/fonts/` | Self-hosted fonts, see "Fonts" below. |
| `assets/favicon.svg` | Browser tab icon. |
| `.nojekyll` | Tells GitHub Pages to serve the files exactly as they are. |

## Publish on GitHub Pages (ye-liu-site)

Upload the **contents** of this folder to the root of the `yeliu918/ye-liu-site` repository, including `assets/` and the hidden `.nojekyll` file. In **Settings → Pages**, choose **Deploy from a branch**, then select the default branch and `/ (root)`. The project site is expected at `https://yeliu918.github.io/ye-liu-site/` once GitHub Pages is enabled and deployed.

To preview locally, run `python3 -m http.server 8000` in this folder and open <http://localhost:8000/>. Opening `index.html` directly from disk also works.

## Publications and highlights

`assets/publications.js` is generated by `build_data.py`, which is kept with the maintainer's tools (`profile-site-tools/`) and is not part of the published site. The script merges the seed list (Google Scholar export), arXiv metadata (`enriched.json`) and the corrections at the top of the script, then overwrites `assets/publications.js`. To change a paper, edit the inputs and run `python3 build_data.py <site folder>` from the tools folder, where `<site folder>` is the folder with this `index.html` (it needs Node.js; without the argument the script writes to `profile-site/site`). A hand edit to `publications.js` is lost the next time the script runs. The script's sections:

- `VENUE_OVERRIDE`, `TITLE_OVERRIDE`, `TYPE_OVERRIDE`, `AUTHORS_OVERRIDE`, `TLDR_OVERRIDE`, `EXTRA_LINKS`: corrections to single papers.
- `EQUAL`: authors marked `*` (equal contribution or lead contributor) on a paper.
- `SELECTED`: the ids shown under "Selected publications".
- `HIGHLIGHTS`: the benchmark claims, see below.
- `RELEASES` and `RELEASES_AS_OF`: the open releases and their Hugging Face download counts, see below.

How the page uses each field of a paper:

- `authors`: comma-separated. "Ye Liu" is bolded automatically. A `*` after a name (`Ye Liu*`) means equal contribution and turns on the footnote under the lists. Lists with more than 10 authors collapse around your name and get a "show all N authors" button.
- `venue`, `year` (a number). `type`: `conference` | `journal` | `workshop` | `preprint` | `report` | `release` (a model release with no paper). The venue is the small badge in the left column of each paper. After the paper's links come a label for preprints, tech reports, workshop papers and model releases, then the authorship mark. Workshop papers get the label only when the venue name does not already say "Workshop". Under "Selected publications" the venue is followed by the year. Under "All publications" it is not, because the papers are grouped under year headings.
- `topics`: `reasoning` | `agents` | `retrieval` | `code` | `qa` | `nlg` | `dialogue` | `llm` | `graph`. A new topic key also needs a label in `TOPICS` at the top of `main.js`; without a label it gets no topic tab. The number of papers per topic shows as a tooltip on each tab and is read out by screen readers.
- `first: true`: first or co-first author. This adds the "First author" or "Co-first author" mark (co-first when your name carries a `*`).
- `selected: true`: the paper is shown in "Selected publications", with its `tldr` under the authors (one line, two on phones, and a "more" button when it is cut off).
- `links`: `arxiv` (bare id, e.g. `2411.12644`), `doi` (bare DOI), and full URLs for `code`, `model`, `data`, `project`, `blog`. The title links to arXiv when there is an arXiv id, otherwise to the first link. With no links, the title opens a Google Scholar search for the exact title.
- `figure`, `figure_alt`, `figure_w`, `figure_h`, `figure_thumb`: the paper's figure, see "Figures" below.
- `id` gives each paper an anchor, `#pub-<id>`. The research themes and the Highlights cards link to these anchors. A link to an unknown id logs a warning in the browser console.

**Highlights** is one grid of cards, one card per artifact: every paper with a `"leaderboard"` highlight or a release. `main.js` builds it from two fields that `build_data.py` writes into each paper:

- `highlights` (from `HIGHLIGHTS`): lists of `{kind, text, url, note, role, bench, scope, when, artifact}` per paper id. `kind: "leaderboard"` puts the claim on the paper's card; `"resource"` is only a badge. Both kinds also appear as badges on the paper (`text`).
- `release` (from `RELEASES`): `{name, kind, url, repos}` per paper id; the script adds the total `downloads`, its short `label` (4.3M, 741K) and `as_of` (`RELEASES_AS_OF`).

Each card shows, from top to bottom:

1. The paper's short name, linked to the paper (`#pub-<id>`), then the release `name` when it is not just the short name with a version suffix (CodeXEmbed is released as SFR-Embedding-Code). Under it the release `kind`, or the highlight's `artifact` for a paper without a release (JudgeRank).
2. The result, if there is a leaderboard highlight: `bench` and `scope`, then `when` (e.g. "Ranked first at release, Jun 2024" or "Ranked first, as reported in the paper (Aug 2025)"), linked to `url`.
3. The downloads, if there is a release: "`label` downloads" (the number in bold), linked to the release `url`, with a bar. The bar is linear, relative to the largest release, and at least 2 px long so small releases stay visible; releases under about 2% of the largest (FOLIO, B3 and SweRank today) therefore all draw at 2 px. Hovering shows "All-time downloads (Hugging Face API, `as_of`)" and the count per repository. Note that the linked Hugging Face page shows last-month downloads, not the all-time count, and for a release with several repositories it is the page of one of them; that is why the lede says only that each *result* links to its source.
4. Your role (`role`, or else First author / Co-first author / Co-author from the author list) and, when there is something to show, "Details": the highlight's `note` and, for releases with several repositories, the count per repository.

The cards are ordered: those with both a result and a release, by downloads; then results without a release; then releases without a result, by downloads. The parts of a card line up with the cards next to it (CSS subgrid), so a card without a result or a release keeps an empty line there. Keep `text`, `when` and `note` no stronger than what `url` supports, with the qualifier ("at release", "as reported in the paper") and the date in the wording itself. The page deliberately has no "#1" numerals, no download totals or count tiles and no state-of-the-art list. Short names are the part of the title before ":", or an entry in `SHORT` in `main.js`.

**Static copy of the cards (keep in sync).** `index.html` also contains a plain copy of the cards, between `<!-- static:hl-cards -->` and `<!-- /static:hl-cards -->`. Only visitors without JavaScript see it; with JavaScript it is replaced by the rendered cards. After you run `build_data.py` or change `main.js`, update the copy:

- Serve the site (`python3 -m http.server 8000`), then run `python3 <tools folder>/sync_static.py http://localhost:8000/ index.html` from this folder (the script is with `build_data.py`, not published; it needs Playwright for Python). It replaces every `<!-- static:ID -->` block with the rendered element `#ID`. Add `--check` to only report whether the copy is up to date.
- Or copy the rendered `<div id="hl-cards">` from the browser's inspector and paste it over the old one.

**Patents**: `window.PATENTS` in the same generated file (from the seed list) is kept for reference only; patents are not shown on the page.

## Figures

Every paper has one figure, `assets/figures/<id>.webp` (WebP, white background, about 1000 px wide, at most about 100 KB), and a 400 px wide copy, `assets/figures/thumb/<id>.webp` (about 12 KB each), for the publication lists. Each publication row shows the figure in the left column, under the venue badge, in a fixed 16:9 white frame (white in the dark theme too, dimmed there), scaled to fit without cropping. Below 680 px wide the left column narrows from 104 to 92 px and stays beside the title and authors in both lists; the TL;DR and links then take the full width. The images load lazily, as they scroll into view, and the browser picks the 400 px copy unless the screen needs more pixels.

The figure button comes after the paper's text in the page source, so screen readers and the Tab key reach the title first; its accessible name is "Enlarge figure:" followed by the description. Clicking it, or pressing Enter on it, opens a viewer (a native `<dialog>`, `id="fig-viewer"` in `index.html`) with the full-size figure, the paper title, the description as caption, the paper's links, an "Open image" link to the file itself and a Close button. Esc, Close or a click outside closes it, and focus returns to the figure. The page behind it does not scroll. On phones the viewer fills the screen and wide figures are shown up to 720 px wide, so they stay readable and can be moved sideways with a finger.

The figure fields in `publications.js` come from `profile-site-tools/figures/manifest.json` (one entry per paper id: `file`, `alt`, `w`, `h`, plus `source` and `label` for your records), read by `build_data.py`:

- `alt` is the one-sentence description: the image's alt text and the viewer's caption.
- `w` and `h` are the image's pixel size; they become the `<img>` `width` and `height`.
- `figure_thumb` is set when `assets/figures/thumb/<id>.webp` exists. Without it the lists use the full image.

To replace a figure, save the new image under the same name, `assets/figures/<id>.webp` (keep the paper id; also copy it into `profile-site-tools/figures/`), and make its 400 px copy in `assets/figures/thumb/`. If its pixel size or content changed, update `w`, `h` and `alt` in `manifest.json` and run `python3 build_data.py <site folder>`. Keep the white background and stay near 1000 px wide and under about 100 KB, e.g. `cwebp -q 82 -resize 1000 0 in.png -o <id>.webp`, then `cwebp -q 80 -resize 400 0 <id>.webp -o thumb/<id>.webp`. A paper without a manifest entry gets no figure, and its text keeps its place in the right column.

## Other edits

**Photo**: to change it, replace `assets/photo.jpg` with another square photo (at least 320×320; the current one is 480×480). It is cropped to the ringed circle at every screen width. The `PHOTO:` comment in the hero of `index.html` says how to show initials instead.

**Email and CV**: these two hero links are hidden for now. In `index.html`, set the email link to `mailto:you@example.com` and put your CV at `assets/cv.pdf`, then delete `data-todo` from that link's `<li>`. The rule that hides them is the `SWITCH` comment near the top of `assets/style.css`. Delete that rule to show both links at once.

**Text**: the Highlights lede, About and the research themes are plain HTML in `index.html`. "Last updated" is in the footer.

**Download numbers**: Hugging Face all-time downloads, fetched 2026-10-19, are typed into `RELEASES` in `build_data.py` (per repository, under `repos`). To update them:

1. Re-fetch the count of each repository listed in `RELEASES` (commands below) and change the numbers there.
2. Change `RELEASES_AS_OF`; it is shown under the cards ("as of Oct 2026").
3. Run `build_data.py` with this folder, then `sync_static.py`, as described above. The totals, labels and bar lengths are computed.

The all-time count is `downloadsAllTime` from `https://huggingface.co/api/models/<org>/<name>?expand[]=downloadsAllTime` for models and `https://huggingface.co/api/datasets/<org>/<name>?expand[]=downloadsAllTime` for datasets (FOLIO). These URLs work as-is in a browser; with `curl`, add `-g` because of the `[]`. To print the model counts:

```sh
for r in Salesforce/SFR-Embedding-2_R Salesforce/SFR-Embedding-Mistral Salesforce/SFR-Embedding-Code-2B_R \
  Salesforce/SFR-Embedding-Code-400M_R VLM2Vec/VLM2Vec-V2.0 raghavlite/B3_Qwen2_2B raghavlite/B3_Qwen2_7B \
  Salesforce/SweRankEmbed-Small Salesforce/SweRankEmbed-Large Salesforce/SweRankLLM-Small Salesforce/SweRankLLM-Large; do
  printf '%s ' "$r"; curl -sg "https://huggingface.co/api/models/$r?expand[]=downloadsAllTime" | python3 -c 'import json,sys; print(json.load(sys.stdin)["downloadsAllTime"])'
done
curl -sg "https://huggingface.co/api/datasets/yale-nlp/FOLIO?expand[]=downloadsAllTime" | python3 -c 'import json,sys; print(json.load(sys.stdin)["downloadsAllTime"])'
```

XGen-7B is not listed among the releases; the XGen paper stays in the publication list.

## Fonts

`assets/fonts/` holds Inter (text) and Source Serif 4 (name, section and theme headings, Highlights card names, year headings, figure viewer title). Both are variable `woff2` files (Latin subset, upright only) under the SIL Open Font License 1.1. The licence texts, `LICENSE-Inter.txt` and `LICENSE-SourceSerif4.txt`, must stay next to the font files. `style.css` declares the fonts with `@font-face` and `font-display: swap`, and `index.html` preloads both files (except on `file://`, where a font preload is a blocked request). If a font fails to load, the page falls back to system fonts.

## Design notes

- Publications: one row per paper. The left column (`--side`, 104 px; 92 px on phones) holds the venue badge and the figure, the right column the title, authors, TL;DR and links. On phones the badge and figure stay beside the title and authors, and the TL;DR and links take the full width.
- Highlights: one card per model or benchmark, so each result sits next to the adoption of the same artifact. Three columns from 1000 px, two on tablets, one on phones (where name and kind share a line). All eight cards fit on one 1280×900 screen after the Highlights link is clicked. The faint band behind the section (`--band`) marks it as the main section of a long page.
- Light and dark themes share one palette definition (the custom properties in `style.css`). The page follows the OS setting until the visitor uses the toggle.
- On narrow screens the section links become a pinned strip that scrolls sideways, and the topic tabs scroll sideways too.

**Browser caching**: `index.html` loads `style.css`, `publications.js` and `main.js` with a `?v=YYYYMMDD` suffix. After you change any of them, bump that number (all three links) so returning visitors get the new files instead of a cached mix.
